# 교환사채(EB) 발행결정

## 개요

이사회에서 교환사채(이미 발행된 주식으로 교환할 권리가 붙은 사채)를 발행할 때 제출하는 의무 공시. CB와 구조가 거의 같으나, **CB는 교환권 행사 시 신주를 발행**하는 반면 **EB는 기존 주식(주로 발행회사의 자기주식, 때로는 보유 중인 타사 주식)으로 교환**한다.

**희석의 성격이 다르다**:
- CB/BW = 신주 발행 → **지분 희석**(주식수 증가)
- EB(자기주식 기초) = 신주 발행 X → 형식적 지분 희석은 없으나, **의결권 없던 자기주식이 교환권 행사로 제3자에게 이전되며 의결권이 부활** → 기존 주주의 **의결권 희석**. 사실상 제3자배정 유상증자와 유사한 지배구조 효과.

행동주의·경영권 분쟁 국면에서 자기주식을 우호 제3자(인수자)에게 EB로 넘기면 우호 지분을 만들 수 있어 **경영권 방어 수단**으로 쓰인다.

## 소스

- **제출처**: [[DART-OpenAPI]]
- **공시 유형**: pblntf_ty=B (주요사항보고) / pblntf_detail_ty=B001

- **공시 주기**: 수시

## 전체 문서 구조 (트리)

```
주요사항보고서(교환사채권 발행결정)
│
├── 1. 사채 기본정보
│   ├── 회차                                    ← bd_tm   (원문: "회차")
│   ├── 사채 종류                                ← bd_knd  (원문: "종류" 단독줄, 예: 무기명식 무이권부 무보증 사모 교환사채)
│   ├── 권면(전자등록)총액 (원)                  ← bd_fta
│   └── 발행방법 (사모 / 공모)                   ← bdis_mthn
│
├── 2. 금리·만기
│   ├── 표면이자율 (%)                          ← bd_intr_ex
│   ├── 만기이자율 (%)                          ← bd_intr_sf
│   └── 사채만기일                              ← bd_mtd
│
├── 9. 교환에 관한 사항
│   ├── 교환비율 (%)                            ← ex_rt
│   ├── 교환가액 (원/주)                         ← ex_prc      ★
│   ├── 교환가액 결정방법                        ← ex_prc_dmth
│   ├── 교환대상 (종류)                          ← extg        ★ (자기주식 여부 핵심)
│   ├── 교환대상 주식수                          ← extg_stkcnt
│   ├── 발행주식총수 대비 (%)                    ← extg_tisstk_vs ★ (의결권 희석률)
│   └── 교환청구기간 시작/종료                   ← exrqpd_bgd / exrqpd_edd
│
├── 자금조달 목적                               ← fdpp_*
├── 사채발행일 / 납입일                          ← sbd / pymd
├── 14. 이사회결의일(결정일)                     ← bddd
└── 인수인 (사모 시)                            ← rpmcmp / 원문 인수인 표
```

| `bd_tm` | 회차 | 회차 | |
| `bd_knd` | 종류 | 사채 종류 텍스트 | "사모" 여부 확인 |

## ⚠️ 정정·철회 시 구조화 응답이 빈다 (중요)

DART 주요사항보고서 **주요정보 API(`exbdIsDecsn.json`)는 정정·철회된 EB를 최신본(철회)만 반환하며, 그것도 교환 조건 필드를 모두 `-`로 비워서 준다.** 즉 발행 후 철회된 EB는 구조화로는 "사건이 있었다"는 흔적(1건)만 남고 교환가액·교환대상·총액이 사라진다.

**알맹이는 원본/정정 공시의 원문 문서(`document.xml`)에만 남는다.** `list.json`(B001, 키워드 "교환사채권발행결정")으로 공시 체인 전체를 받아, **원본(가장 오래된)** 문서를 파싱하면 발행조건이 가장 완전하게 복원된다(후속 정정본은 재검토 중 필드가 다시 `-`로 비기도 함).

또한 **첨부정정만 있는 체인**은 구조화 API가 013(0건)을 반환해 EB가 **통째로 누락**되기도 한다(한라IMS: 구조화 0건, list.json엔 `[첨부정정]` 1건). 이때 그 첨부정정 문서의 `document.xml`마저 014(파일 없음)이면 원문 추출도 불가하다.

- OPM 대응: 구조화 응답이 비면 원본 공시 원문을 파싱해 복원하고, 구조화 0건이어도 list.json에 EB가 있으면 원문에서 행을 만들며, 문서마저 없으면(014) "EB 공시 발견, 원문 확인 필요" 탐지 전용 행으로 남긴다 — *no_filing 오인 방지*. 상세는 tools/ 카탈로그 참조.

## OPM에서의 활용

- **교차 확인**: 교환대상이 자기주식이면 [[자기주식취득결정]]과 교차 — 회사가 사 모은 자사주를 EB로 제3자에 넘기는 흐름.

## 거버넌스 분석 포인트

1. **교환대상이 자기주식인가 (`extg`)**: 그렇다면 신주 희석이 아니라 **의결권 희석**. 누가 인수자(우호 지분 수혜자)인지가 핵심.
2. **사모 발행 (`bdis_mthn=사모`)**: 인수자 지정 → 경영권 방어/우호지분 형성 가능성. 2대 주주·행동주의 대응 맥락 점검.
3. **의결권 희석률 (`extg_tisstk_vs`)**: 발행총수 대비 비율. 10%+면 지배구조 영향 주목, 20%+면 심각.
4. **표면금리 0% + YTM 0%**: 교환권 가치로 보전. 자기주식 처분(저가 교환가) 적정성 논란 소지.
5. **철회 여부**: 가처분·여론·정책(자사주 의무소각 등)으로 철회되는 사례 — 최신 공시 상태 확인 필수.
