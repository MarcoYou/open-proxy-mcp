# 보수한도 · 소진율

## 개념

주주총회에서 이사(또는 감사)의 **보수 최고 한도액**을 승인하는 보통결의 안건. 한도 자체보다 **전기 실지급액 대비 한도**인 **소진율**로 읽는다 — 소진율이 낮으면 한도가 과다 설정된 것, 높으면 한도가 빠듯한 것.

## 소진율 — 공식은 하나

```
소진율(%) = (감사 단독 제외한 이사류 실지급 합) ÷ 이사 주총 승인한도 × 100
```

- **분자**: 사내이사·사외이사·감사위원 등 **이사류 전부**의 실지급 합(사업보고서 「이사·감사 전체의 보수현황」 유형별 표). 감사위원은 이사이므로 포함, 감사(비이사)는 별도 한도라 제외.
- **분모**: 같은 연도의 주총 승인 한도(`drctrAdtAllMendngSttusGmtsckConfmAmount`).
- 예: 삼성전자 — 전기 실지급 287억 ÷ 전기 한도 360억 = **79.7%**.
- **100% 초과는 버그가 아니라 실제 신호**다 — 퇴직금 지급, 한도 안건과 실지급 인원 범위 불일치 등 원인이 갈린다. `director_board` 는 `utilization_flag="exceeded_limit"` 로 표시하고 비고에서 사유를 찾는다.

## 거버넌스 분석에서의 의미

- 전기 소진율이 낮은데 한도를 유지·인상하면 주주 반대 가능성이 높아진다. 한도 안건 판정에 **전기 실지급액은 필수 입력**이다.
- 높은 소진율(80%+)이면 다음 기 인상 안건이 나올 가능성이 높다. 「한도 거의 소진 + 인상 요구」는 인상 근거가 있다는 신호(현대차 실측: 작년 소진율 100% → 제안 +19.8%).
- 절대 기준은 없다 — 동종 업종 비교·추이로 본다.

## OPM에서의 처리

- `shareholder_meeting_notice`(`compensation` scope): 소집공고의 보수한도 안건에서 올해 제안(current)·작년 한도+실지급(prior)을 읽는다. 이사/감사 별도 안건일 수 있고, 금액 단위(억원·백만원·천원)가 제각각이라 **원 단위로 정규화**한다.
- `director_board`(`compensation`·`pay_agenda` scope): 정형 API 로 연도별 소진율, 안건 대비 작년 실적(인상률·작년 소진율)을 낸다. 「작년 소진율」은 소집공고 prior 컬럼과 정형 API 두 소스가 있어 어느 쪽 값인지 응답이 밝힌다.
- 의결권 판정(`proxy_advise_before_meeting`)에서 보수 과다·소진율 낮은데 인상은 **REVIEW** 사유다(AGAINST 아님).
