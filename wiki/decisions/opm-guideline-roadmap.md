# OPM guideline v2 · 로드맵과 이행현황

이 문서는 **어디까지 완료했고 무엇을 해야 배포할 수 있는지** 보여준다. 판단 원칙·설정·출처 기준은 [가이드라인](260908_1200_decision_guideline-v2-final-redesign-pilot.md)에 둔다. 수치는 2026-09-11까지 확인한 실행 기록 기준이다.

## 현황·로드맵

> **현재 04 · 판정 교정과 품질 검증 단계다.** 전량 보고서 평가는 완료했지만 전 안건의 평가를 MCP 제품 권고에 적용하는 공통 연결은 남아 있다. 후보·선출 구조에 이미 있는 제출 경로와 구분한다. 운영 배포 완료 상태가 아니다.

기존 01~06 단계 번호를 유지한다. 완료는 그 단계의 명시된 범위가 끝났다는 뜻이며, 전체 제품의 완성도 퍼센트가 아니다.

| 단계 | 상태 | 도달점 | 완료한 것 | 남은 일·완료 기준 |
|---|---|---|---|---|
| 01 | 완료 | 설계·정책 계약 | Astra·Fable 관점 통합, 정책 JSON, 후보·구조 평가 계약과 사용자 설정 정의 | 사외·독립이사와 선출 구조의 최소 계약 범위. 범용 고객 정책 운영은 추가 범위다. |
| 02 | 완료 | 실제 MCP 연결 | 공개 원문 → 호출 LLM → 제출 검증 → 후보·구조 권고 연결을 실제 MCP에서 확인 | 모든 안건의 공통 LLM 제출 계약이 완료된 것은 아니다. |
| 03 | 완료 | 유연한 LLM 흐름 | 원문 직접 판독·추가 독해, 누락 기준 제외, 과업별 오류 격리, 숫자 설정과 자동·수동 분기 | 원천 탐색은 제한된 범위이며 모든 필요한 자료를 찾는다는 보장은 없다. |
| 04 | 현재 도달 | 제품 연결·품질 검증 | 전량 비교 12회차·239행 완료. 구조 온톨로지·4단계 판독/해석/권고/QA와 영원무역 2안건 실제 MCP 적용·오류 격리 확인 | Luna 실제 비교, 독립 의미 검증, 전 안건 제출 연결, 경합 선택 처리 |
| 05 | 다음 착수 | 출시 운영 준비 | 실행·정책·설정 연결, 사람 미검토 표시와 수동 지정·증분 조회의 기반 확보 | 출시 범위와 기본값, 정책 활성화·복구, 수동 인계·오류 대응을 검증 |
| 06 | 남음 | 범위 한정 배포 | 로컬 파일럿과 문서·보고서까지 확인 | 사용자 요청으로 커밋·푸시 및 main CI 배포 후 live MCP의 과업·제출·최종 권고·분기를 확인 |

### 바로 다음 작업

**단계별 구조 경로를 Luna로 실제 실행하고, 원문 대조로 품질을 확인한 뒤 전 안건으로 넓힌다.** 구조 영역의 사실·표결 종류 고정과 QA 제출은 연결했다. 일반 배당·보수·재무·재편 안건의 공통 제출과 경합 선택 해결은 남아 있다. 모델끼리의 결론 일치율만으로 다음 단계에 진입하지 않는다.

실측 전 [모델 비교·바이어스 검증 설계](opm-model-evaluation-protocol.md)를 고정한다. 사람 미검토와 유료 API 사용은 허용된 상태다. Luna·Terra·Sol·Astra의 공통 설정, 새 문맥, 원문 시점, 직접/단계별/연산 대조군과 채점자 검증을 분리한다. 현재는 설계 단계이며 이 조건의 모델 비교 결과는 아직 없다. [읽기용 실험 설계서](../../output/model-evaluation-design-20260911/index.html)

## 남은 작업과 완료 기준

아래 순서로 진행한다. 새 파서를 늘리는 것을 완료 조건으로 삼지 않는다. 원문을 직접 읽어 해결할 수 있는지 먼저 보고, 자료가 없으면 해당 기준만 제외해 다른 안건은 계속 처리한다.

| 순서 | 할 일 | 완료로 인정할 증거 |
|---|---|---|
| 1 | 공통 사실·표결 목록 확정 | 같은 원문에서 상위/개별 안건, 후보·좌석 수, 가결·부결 조건을 먼저 공유. 동명 후보와 계속 재직자를 구분 |
| 2 | 전 안건 평가 제출 연결 | 보고서에만 있던 판단을 실제 MCP에 제출하고, 수용·거절 이유와 최종 권고를 JSON·Markdown에서 확인 |
| 3 | 경합·조건·선택 처리 | 대안별 수용 가능성과 실제 선택 우선순위를 분리. 최대 선택 수·집중투표 배분·철회·조건을 위반하지 않음 |
| 4 | 남은 원문·설명 공백 보강 | 관계 회사의 인사 공시, 이미지 본문, 후보 수·자리 수 설명을 추가로 읽고 영향받은 행만 갱신 |
| 5 | 의미 품질 검증 | 같은 설정 반복, 다른 모델·새 표본, 독립 실무 검토에서 사실 귀속·시점·스킵·정책 해석 오류를 별도로 측정 |

### 모델 의존도를 낮추는 경로의 이행현황

| 장치 | 현재 도달점 | 남은 검증 |
|---|---|---|
| 4단계 작업 계약 | 정관·선출 구조에서 사실 → 해석 → 권고 → QA를 별도 입력·스키마로 실행 | Luna의 최초 원문 판독부터 반복 실행 |
| 사실·표결 범위 고정 | 투표 성향과 분리한 판독, 명시적 사실 묶음 재사용, 원문 변경 시 무효화 | 관계·기간·시행 조건의 의미를 잘못 읽는 비율 |
| 온톨로지 | 기준·사실 타입·원천 안내·QA 질문의 연결을 코드와 공유 | 안내한 모든 원천의 자동 탐색이나 수집 완료를 뜻하지 않음 |
| 검증·격리 | 바뀐 판단에 옛 QA 사용 금지, 오류 항목 기록, 독립 안건 유지 | 단계별 의미 오류의 자동 수정 전략과 실무 검토 |
| 모델·비용 분리 | 앱 callback 교체, 단계별 예산, 강한 모델 자동 전환 없음 | Luna 성능·시간·총 호출량 측정. 비용 절감은 미확인 |

이 경로는 `protocol=staged`로 선택한다. 기존 direct 구조 제출과 후보 경로의 동작을 유지한다. 출처 묶음에는 아직 긴 문맥이 들어올 수 있으므로 단계를 나눴다는 사실만으로 작은 모델의 품질을 보장하지 않는다.

완료한 전량 비교에서 나온 구체적 과제와 수정 상태는 아래 목록에 표시한다. 이 목록은 [실제 비교 보고서](../../output/firmness-all-samples-20260911/index.html#issues)의 과제 기록을 사용한다.

## 검증 결과와 읽는 법

### 단계별 하네스의 실제 MCP 결과

영원무역 정기주총의 **정관 안건 두 개만** 단계별로 작성해 실제 로컬 HTTP MCP에 제출했다. 나머지 13행은 미평가로 유지했다. 전체 회차 완료가 아니다.

| 안건 | 수용된 판단·MCP 최종 권고 | 처리와 이유 |
|---|---|---|
| 이사의 수 | REVIEW | 상한 8명 자체를 위반으로 판단하지 않음. 시행 시점의 구성·업무량 대조가 남아 사람 검토 |
| 집중투표 배제 금지 | FOR | 배제 문구 삭제 제안에 찬성. 장래 적용례 보존. 기존 법률 제약이 있어 처리 단계는 사람 검토 |

| 실제 MCP 오류 주입 | 수용된 판단 수 | 확인한 결과 |
|---|---:|---|
| 정상 제출 | 2 | 두 권고와 QA 연결 |
| QA 뒤 한 안건 판단 수정 | 1 | 수정된 안건만 제외, 다른 안건 찬성 유지 |
| 한 안건 QA에 미해결 문제 표시 | 1 | 해당 안건만 제외, 다른 안건 찬성 유지 |
| QA 전체 누락 | 0 | 두 평가 모두 수용하지 않음 |

판독과 QA는 **같은 데스크탑 Astra 문맥**에서 수행했다. 직접 유료 모델 API와 Luna 호출은 0건이다. 이 표는 제품 연결·고정 조건 검증이며 독립 의미 정확성 검증이 아니다. 오류 주입 건수를 실제 사실 오류 발견 건수로 세지 않는다.

전체 회귀 2,457개 통과 후, 잘못된 사실 항목의 격리를 보강한 관련 회귀 176개도 통과했다. Wiki·도구 카탈로그·문서 계약 검사도 통과했다. 용어 점검에는 기존 다른 서비스의 35건이 남아 있으며 이번 변경 파일의 신규 지적은 없다.

### 이전 전량 비교와의 구분

**전량 보고서 평가 완료와 제품 적용 완료를 구분한다.** 다음 실행들은 대상과 제출 방식이 달라 서로 합산하지 않는다.

| 확인한 실행 | 대상 | 도달점 | 이 결과로 주장하지 않는 것 |
|---|---|---|---|
| 이전 후보 파일럿 | 10개사·11회차, 지원 후보 39과업 | 실제 MCP에서 최종 수용. 조건부 중복 포함 42개 적용행 | 전 안건·독립 의미 정확성·운영 배포 완료 |
| 이전 정관 보강 실험 | 5개사·6회차, 구조 판단 45개 | 원문 추가 후 실제 구조 판단 수용 | 완전한 정관·판결문 전문 확보 |
| 최신 firmness 비교 | 기존 10개사＋카카오, 정기 11회·고려아연 임시 1회 | 239행을 .1/.9 각각 평가. 보고서 판단 478개 완료 | 새 전량 평가를 native MCP에 제출·적용했다는 뜻 |
| 박병욱 원문 보강 | 조건부 2행 × 두 설정 | 사임 공시 추가 후 4개 평가 완료. 결론 유지·현재 겸직 설명 수정 | 찬반 변화가 있어야만 품질이 개선된다는 해석 |

최신 비교는 stance=0.5·automation=0.5를 고정하고 firmness만 0.1/0.9로 달리했다. 각 주총일 00:00 KST를 마감으로 삼고 날짜만 있는 공시는 전일까지 허용했다. 모델 평가는 데스크탑 Astra 세션에서 수행했다. 정성 결과는 모두 사람 미검토다.

<!-- report:firmness -->

안건 행에는 상위 제목·조건별 대안·철회가 포함되므로 고유 투표 수가 아니다. 같은 설정을 반복하거나 다른 모델과 비교한 정확성 실험도 아니다. 변화 수·수용률·주총 가결 결과를 정답으로 쓰지 않는다.

### 확인한 개선과 남은 한계

- 구조 평가 대상이 없는 과업은 완료 상태로 종료하며 수용한 판단 수에는 포함하지 않는다.
- 실제 후보 과업이 없는 내부이사·묶음 행에 존재하지 않는 선행 평가를 요구하지 않도록 고쳤다.
- 태광산업의 긴 공고에서 빠진 텍스트 구간을 추가했다. 텍스트 전체 확보와 이미지 독해는 별도다.
- 박병욱의 사임, 삼성전자 심의 연도, 김대근 동일인 추론을 보강·교정하고 초기 기록을 보존했다.

관련 전체 회귀 검사는 2,437개 통과했다. 전량 보고서의 ID·인용 문자열·자료 공개일·양쪽 입력 연결 검사도 통과했다. 이 검사는 자료의 완전성이나 의미 정확성 인증을 대신하지 않는다.
