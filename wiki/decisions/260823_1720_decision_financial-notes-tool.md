# financial_notes tool — 금융사 재무제표 주석 표 원형 추출

> 은행·증권·보험의 **연결/별도 재무제표 주석**에서 ①투자자산 유형별 구성(FVPL·FVOCI·상각후원가)
> ②사용제한 예치금·담보제공자산 표를 **가공 없이 원형 그대로** 뽑는 tool 의 스코프·계약.
> 근거 census: 21사 41건(반기 21·사업 20), `/tmp/census/result.json` → storage 이관 예정.

## 왜 (배경)

크레딧/채권 애널리스트 요청. 두 용도가 명확하다.

- **사용제한 예치금** → `unencumbered cash/cash equivalent` 산출.
  기본 산식 = (재무상태표 현금및현금성자산 + 주석 예치금) − (사용이 제한된 예금·예치금).
  부채상환능력(유동성) 평가에 쓴다.
- **투자자산 유형별 구성** → 자산건전성. 국공채/특수채/금융채/회사채/주식 등 **유형별로 다른
  헤어컷**을 적용해 자본과 대비, 손실흡수력을 본다.

기존 tool 로는 안 된다. `financial_metrics` 는 전사 집계라 주석 내부 분해가 없고,
`business_details` 는 **「II. 사업의 내용」** 담당이라 문서 안의 다른 장이다(이 건은 「III. 재무에 관한 사항」).

## 무엇이 어려운가 (census 실측)

🔴 **형식이 회사가 아니라 표 단위로 갈린다.** 41건 실측.

| 표 | 표구조(TD) | XBRL 태그(TE) | 못찾음 |
|---|---|---|---|
| 사용제한 | 51% | 41% | 7% |
| FVPL | 75% | 24% | — |
| FVOCI | 90% | 9% | — |
| 상각후원가 | 65% | 34% | — |

**업권으로 분기하면 절반이 틀린다.** 사용제한 기준 은행 표구조 10:2 · 보험 태그 9:3(정반대) ·
증권 8:6(혼재). 같은 회사 안에서도 표마다 다르다(국민은행 FVPL=태그, FVOCI=표구조).

→ **판별은 표마다 런타임에 한다**: 그 `<TABLE>` 안에 `<TE ACODE=...>` 가 있으면 태그 경로,
없으면 `<TD>/<TH>` 구조 경로.

### 태그 경로가 유리한 이유

`<TE>` 는 값마다 IFRS 요소와 문맥을 달고 있다.

```
ACODE="ifrs-full_FinancialAssets"
ACONTEXT="CFY2026eHYA_..._ConsolidatedMember_..._dart_SeparatePortionOfCustomersDepositsMember"
>8,911,269</TE>
```

「2026 반기 · **연결** · 투자자예탁금별도예치금 · 금융자산」이 값 자체에 박혀 있다.
애널리스트가 「투자자예탁금별도예치금(신탁)은 **빼면 안 된다**」고 한 그 구분이 **기계로 된다.**

⚠️ `ACODE` 어휘는 표준이 아니다 — `ifrs-full_*`(국제표준) · `dart_*`(DART 확장) ·
`INV_*`·`BSS_*`(사업보고서 서식 필드코드, 재무제표 아님). 고유 코드 774~1,394종/사.
**표준 코드만 가정하면 안 된다.**

### 앵커 — 실측 적중

사용제한 41건 기준: 「사용이 제한된」 32 · 「사용이 제한되어」 4 · 「사용제한 예치금」 2 · 못찾음 3.

🔴 **못 찾은 3건은 표현이 다른 것이지 없는 게 아니다.** 현대해상·미래에셋생명은
**「담보제공자산」**(「부채나 우발부채에 대한 담보로 제공된 금융자산」)으로 공시한다.
「사용이 제한」이 문서에 **0회**다.

→ 앵커에 `담보제공자산`·`담보로 제공된 금융자산` 추가.
⚠️ **다만 「사용제한」과 「담보제공」을 산식에서 같게 볼지는 애널리스트가 정할 문제다.**
담보 제공은 소유권이 남고 사용제한은 인출이 막힌 것이라 회계상 다르다. **tool 은 둘을
구분해 내보내고 합치지 않는다.**

## 계약 (설계 결정)

1. **원형 보존.** 임의로 합치거나 나누지 않는다. 열 이름·사유 열(「사용제한 내용」)·행 순서를
   그대로 낸다. 회사마다 표가 다른 것 자체가 애널리스트에게 정보다.
2. **모든 값에 기준을 붙인다** — 기간(당기말/전기말/당반기말) · 연결/별도 · 단위.
   🔴 실측 근거: KB손보 사용제한 합계가 **전기말 391,082 → 당반기말 26,356**(1/15). 시점을 안
   밝히면 그대로 틀린 분석이 된다. 단위도 회사마다 다르다(백만원/천원/**원** — 미래에셋생명).
3. **여러 표를 한 번에.** `fields="사용제한,FVPL,FVOCI,상각후원가"`. 문서 다운로드는 회사당 1회다.
4. **결측 3분류**(`business_details` 규약 따름) — `NOT_APPLICABLE`(그 주석이 없음) /
   `NOT_COLLECTED`(문서를 못 받음) / `EXTRACTION_FAILED`(표를 못 읽음). **셋을 뭉개지 않는다.**
5. **판단하지 않는다.** unencumbered cash 계산·헤어컷 적용은 tool 밖이다. tool 은 표까지다.

### 성능

문서는 통째로 받는다 — DART `document.xml` 은 **부분 조회가 없다**. 다만 실측상 부담이 작다.

- 내려받기는 ZIP 이라 삼성화재 사업보고서 **1.5MB**(풀면 32MB, 20배 압축)
- 캐시가 서비스 16개 공용 · 두 번째부터 DART 왕복 없음(디스크 적중 0.02초)
- **비용은 통신이 아니라 메모리·시간이다.** 32MB 문자열을 통째로 정규식에 넣지 않는다 —
  ① 「III. 재무에 관한 사항」 이후로 범위를 좁히고 ② 앵커 위치 ±수만 자만 잘라 파싱한다

## 함정 (실측)

- **`[첨부정정]` 은 원문이 없다** — DART 상태 `014`. 삼성화재 사업보고서가 여기 걸렸다.
  → 정기보고서 목록에서 `[첨부정정]` 을 만나면 **같은 보고서명의 직전 접수건으로 폴백**한다
  (삼성화재도 원본 `20260312001399` 는 정상 2,675만 자).
- **문서가 크다** — 한화생명 사업보고서 3,660만 자. 회사 간 편차 3배 이상.
- **띄어쓰기가 흔들린다** — 같은 KB손보 안에서 연결 「사용제한 내용」 · 별도 「사용제한내용」.
  열 이름 매칭은 공백 제거 후 비교한다.
- **반기보고서에도 주석이 다 있다** — 「분기는 축약」 우려는 반기에는 해당 없음(NH 91만 자,
  「사용이 제한」 28회). **분기보고서는 아직 안 봤다** [미확인].

## 남은 것 [미확인]

- **분기보고서 커버리지** — 반기까지만 확인했다.
- **표 파싱 정확도 검증** — census 는 「표를 찾았나·형식이 무엇인가」까지다.
  **뽑은 숫자가 원문과 맞는지는 아직 안 쟀다.** 손 정답지가 필요하다.
- **「사용제한 vs 담보제공」 처리** — 애널리스트 확인 대기.
- **SPC(연결대상 종속회사·타법인출자현황)** — 이번 조사 범위 밖. 정형 API 존재 여부부터 확인 필요.
- **웹서치 연계**(SPC 기초자산 조회) — 애널리스트가 「나중에」로 분리.

## 곁가지 — 디스크 캐시 gzip 전환 (260823 별건 처리)

이 조사 중 캐시가 평문이라 문서 하나가 40MB 씩 쌓이는 것을 발견했다. **별건으로 먼저 고쳤다** —
`.json.gz` 저장(실측 42.2MB→2.0MB, 4%), 옛 평문은 읽기 호환, 청소·집계가 두 형식을 함께 센다.
푸는 비용 0.01초. 시험 863건 통과. **금융사를 본격적으로 다루면 이게 없으면 볼륨이 찬다.**
