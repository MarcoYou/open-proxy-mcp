# 반복 조회 레시피

정해둔 회사와 기간을 반복 조회해 공시 요약을 만드는 프롬프트 모음입니다.
OPM은 조회 도구를 제공하며, 예약 실행과 알림은 연결한 클라이언트의 기능입니다.
이 문서를 읽거나 프롬프트를 붙여 넣는 것만으로 예약이 생성되지는 않습니다.

| 레시피 | 하는 일 | 사용하는 도구 |
|---|---|---|
| [아침 공시 요약](screener-morning-digest.md) | 수주·임시주총·정기주총의 신규 공시와 정정 구분 | screener |

## 처음 설정할 때

1. 레시피의 `{범위}`를 실제 회사명·종목코드 또는 조회할 시장 범위로 바꿉니다.
2. 먼저 수동 실행해 연결, 조회 범위, 원문 링크와 누락 경고를 확인합니다.
3. 사용 중인 클라이언트가 예약 실행에서도 OPM 연결과 필요한 인증을 사용할 수 있는지 확인합니다.
   로그인한 대화에서 도구가 보인다는 사실만으로 무인 실행까지 보장되지는 않습니다.
4. 시간대, 실행 주기, 휴일 처리, 결과를 받을 위치를 예약 화면에서 정합니다.
5. 실제 예약 실행의 결과를 확인합니다. 실패·일부 조회·정상적으로 찾지 못한 경우를 구분해야 합니다.

| 방식 | 확인할 점 |
|---|---|
| 내 컴퓨터에서 실행 | 컴퓨터 절전·앱 종료·네트워크 단절 때 실행되는지, 재개 시 누락분을 어떻게 처리하는지 |
| 서버에서 실행 | 해당 환경의 MCP 연결·인증·외부 통신 지원, 실행 한도와 알림 설정 |

지원 메뉴와 인증 방식은 클라이언트마다 다릅니다. 저장소나 개인 접근 토큰이 반드시 필요한 것은
아니며, 특정 앱의 예약 명령을 모든 환경에 공통으로 적용하지 않습니다. 비밀키를 프롬프트·문서에 넣지 마세요.

## 매번 지켜야 할 것

- **대상과 기준일을 고정합니다.** 제목에도 실제 조회 범위와 기간을 씁니다. 월요일·연휴에는
  지난 실행 이후의 날짜를 포함하고, 이미 본 접수번호는 호출자 쪽에서 구분합니다.
- **결과와 누락을 함께 보여줍니다.** 일부 페이지만 읽었다면 전체 시장의 결론으로 쓰지 않습니다.
  조회 실패를 “공시 없음”으로 바꾸지 않습니다.
- **호출 예산을 제한합니다.** 도구 호출 횟수와 내부 원천 요청 횟수는 다릅니다. 이어받기는 응답에
  실제로 제공된 인자만 사용하고, 제한·차단 신호가 오면 수집을 중단합니다.
- **신규와 정정을 구분합니다.** 정정 전 값을 못 찾으면 현재 값과 원문 링크만 제시하고 그 한계를 적습니다.
- **알림은 결과 중심으로 씁니다.** 일정한 제목·항목 순서를 유지하고, 미확인 값은 미상으로 남깁니다.

실패 대응과 추가 조회는 [도구 연결 안내](../TOOL_CALLING.md), 도구의 실제 인자는
[도구 카탈로그](../../wiki/tools/README.md)가 기준입니다.
