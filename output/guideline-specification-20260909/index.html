적용 범위와 원칙

판단시점 뒤의 정보를 사용하지 않는다. Peeking 금지가 가장 강한 규칙이다. 정기·임시주총마다 회사, 소집공고, 판단 마감시각을 따로 고정한다. 날짜만 확인되는 공시는 마감일 전일까지 허용한다. 나중의 판결·정정·주총 결과를 앞선 시점의 근거로 끼워 넣지 않는다.

파싱은 원문을 찾고 읽는 보조 수단이다. 추출이 실패하면 LLM이 허용된 원문을 직접 읽고 인용한다. 원문에도 없는 사항은 해당 기준만 건너뛰고, 무엇을 건너뛰었는지 알린다. 모르는 값을 0, 관계 없음, 위반 사실로 바꾸지 않는다.

원칙 실제 적용
같은 시점의 근거 공개일·사건일·효력일을 구분한다. 당일 공개 순서가 불명확한 자료도 제외한다.
사실·추론·의견 구분 원문의 사실, 당사자 주장, LLM의 해석을 따로 적고 반증도 읽는다.
해당 기준만 제외 미공개·미기재는 그 기준만 스킵한다. 미독·조회 실패·충돌은 별도 상태로 남긴다.
설정과 고정 조건 분리 판단 선호를 바꿔도 시점·신원·인용·확인된 결격·표결 제약은 유지한다.
판단과 처리 분리 찬반 권고, 사람 검토, 실제 선택·표 배분은 다른 결과다. 현재 투표 전송은 지원하지 않는다.

현재 적용 범위

vote_style=opm_guideline_v2의 기본 shadow는 기존 권고를 유지한다. 명시적인 pilot에서는 수용된 후보·선출 구조 평가를 해당 권고에 반영한다. 서버가 모델을 직접 호출하지 않는다. 호출 AI가 원문을 읽고 평가를 같은 MCP에 제출한다.

회사 거버넌스·분쟁 공개매수·지분·소송·재편과 후속 공시 기업 검토 과업·추가 독해·증분 조회 지원
배당·보수·성과·일반 구조변경 아래의 조사 원칙으로 원문을 읽고 판단 기존 엔진과 보고서 평가는 존재. 전 안건의 공통 v2 제출·권고 연결은 아직 없음

세 가지 사용자 설정

stance는 무엇을 엄격하게 볼지, firmness는 불확실성을 남기고도 결론을 낼지, automation은 나온 결과를 어떻게 처리할지 정한다.

설정 기본값 0에 가까우면 1에 가까우면
stance 0.5 임박한 금전 손실이 입증되지 않으면 찬성 선호 주주권 조항·환원 적정성·경영진 성과까지 적극 검토
firmness 0.75 애매한 결론은 검토로 남김 가정과 한계를 설명하면서 근거 있는 찬반을 선호
automation 0.5 사람 검토 범위 확대 완료된 평가의 찬반을 자동 처리 준비로 보냄

stance와 firmness는 LLM에게 전달하는 연속적인 선호다. 확률·정확도·temperature 또는 일정한 찬성 비율이 아니다. 높은 stance도 구체적 사실에 근거해야 하며, 높은 firmness가 중요한 주주권 문제를 사소하게 바꾸도록 하지 않는다.

automation 처리 기준

값 완료된 찬성 완료된 반대 평가 후 미결
0 사람 검토 사람 검토 사람 검토
0 초과~0.5 자동 처리 준비 사람 검토 사람 검토
0.5 초과~1 미만 자동 처리 준비 자동 처리 준비 사람 검토
1 자동 처리 준비 자동 처리 준비 stance < 0.5는 찬성, stance ≥ 0.5는 반대

automation=1의 미결 처리에는 사용자 기본 정책 적용이라는 표시와 원래 평가·미결 이유를 함께 남긴다. 사실을 확인한 찬반과 구분한다. 미제출·거절된 평가는 완료된 미결이 아니므로 기본값으로 덮지 않는다. 철회·상위 제목 등 NO_VOTE도 유지한다.

firmness=0과 automation=1을 함께 쓸 수 있다. 분석은 불확실성을 남기고 최종 방향은 사용자 기본 정책이 정한다. 집중투표 배분이나 조건부 연결이 남으면 찬반 방향과 별도로 실행 대기를 표시한다. 실제 투표 전송은 항상 0건이다.

특정 안건을 수동으로 지정할 수 있다. 다만 automation=1과 수동 지정은 상충하므로 함께 받을 수 없다. 출석 문턱은 별도로 50~100%에서 설정하며 미지정 시 75%다.

안건별 판단 기준

기관의 찬반을 그대로 복사하지 않는다. 선택한 OPM 정책과 안건의 경제적·지배구조상 효과를 연결한다. 일반 조사 지침과 실제 v2 평가 계약의 범위는 첫 절의 표를 따른다.

안건 먼저 읽을 정보 구분할 점
재무제표 감사의견, 작성·감사 상태, 정정, 주요 불확실성 미완료 감사와 부적정 의견, 조건부 보고 전환
배당·자사주·환원 연결/별도 이익, 영업현금흐름, 순현금·차입금, 투자·상환 수요, 약속 이행 배당액 자체보다 지속 가능성과 주주가치 영향
후보 선임·해임 현재·과거 직책, 선임구분, 독립성, 전문성, 출석, 개인 책임 이름 일치만으로 동일인 확정 금지. 법인 제재와 개인 결격 구분
보수·퇴직금·주식보상 전년 한도·집행액, 증액률, 다년 성과, 산식·성과지표·이연·회수 조건, 희석 한도와 실제 지급 구분. 미공개 산식을 성과 미연계 사실로 바꾸지 않음
정관·선출 구조 전후 조문, 유효 정관, 실제 임기·계속 재직자, 선택 순서 문구보다 권리·교체 기회의 변화
분할·합병·증자·감자 거래 구조·비율·평가 근거, 자금 목적, 희석, 지배권, 소수주주 보호·반대권·조건 구조변경 자체로 악재를 단정하지 않고 구체적 손익·이해상충 평가
주주제안·경합안 제안자, 대안별 효과, 가결·부결 조건, 최대 선택 수 각 대안의 수용 가능성과 실제 선택을 분리

후보 독립성과 출석

독립성은 회사·경영진·지배주주·제안주주와의 고용, 자문, 보수, 중요 거래 등 구체적 관계와 감독상 영향을 본다. 주주가 추천했다는 사실만으로 반대하지 않는다. 공개자료에서 우려를 찾지 못했다는 것은 실제 관계 없음의 보증이 아니다. 사임 공시는 현재 관계를 갱신하지만 과거 관계까지 지우지 않는다.

출석 기본 기간은 직전 완료 사업연도 중 실제 직무 수행 대상 기간이다. 임기 전체 기록은 보조 근거다.

  • 분모는 참석 대상 이사회 회의 수, 분자는 실제 참석 수다. 안건 수·위원회 회의를 섞지 않는다.
  • 중도선임·사임·법원 직무정지 구간을 근거로 반영한다. 단순 불참 소명과 법적 직무 제외는 별도다.
  • 구간별 참석·대상 횟수를 합산한다. 퍼센트 단순 평균과 임의 분모는 사용하지 않는다.
  • 짧은 재직·적은 회의 수는 대표성 한계로 설명한다. 확인된 계산을 막는 별도 최소 회의 수는 없다.
  • 기간·회의 목록을 확정하지 못하면 해당 기준의 공백을 표시한다. 전년 수치를 최신 연도라고 바꾸지 않는다.

현재 후보 파일럿은 재선임 후보의 출석이 문턱 미만이고 수용된 예외가 없으면 반대 기준을 적용한다. 수용된 독립성 우려도 반대 기준이다. 누락과 수용된 반대 근거를 구분하며 확정된 반대 근거를 찬성으로 덮지 않는다.

근거와 시점 관리

공시 제목은 읽을 자료를 찾는 단서다. 제목의 존재나 기사 수를 우려의 강도로 쓰지 않는다. 공개일·사건일·효력일·설명 대상 기간을 함께 기록한다.

원천 활용 목적 주의점
소집공고·소집결의·위임장 안건, 후보, 전후 조문, 제안자·조건 정정·철회와 상위 제목·개별 표결 구분
정기·임시 주총결과 이후 시점의 정관·임원 이력 해당 주총의 사전 판단에 그 주총 결과를 사용하지 않음
사업·반기·분기보고서 재무·임원·출석·거래·첨부 정관의 단서 정관이 항상 첨부된다고 가정하지 않음. 대상 기간과 공개일 구분
지배구조보고서 위원회·책임·보상·주주권 운영 작성 시점과 실제 관행, 설명과 사실 구분
이사 선임·해임·중도퇴임, 대표이사 변경 역할별 현재·과거 직책과 효력 명칭 변경·동일인 확인. 대표권 변경을 이사회 퇴임으로 바꾸지 않음
공개매수·5%·지분·소송·재편 공시 분쟁과 후속 사건 연결 보유 계약·예정 취득·실제 결제·의결권 구분
공정위 결정문·법원 원문 제재·판단의 내용·귀속·후속 변경 법인/개인, 행정/형사, 처분/확정/불복 구분
공정위 회사·임원·주주 데이터 기업집단·지분·겸직 관계 보조 확인 관계도 자체로 위법·종속·독립성 훼손을 확정하지 않음

공정위 자료는 연결할 때의 조사 기준이다. 현재 v2가 위 API를 일반적으로 자동 조회·적용한다고 가정하지 않는다. 원천별 연결 상태는 로드맵에서 확인한다.

기사 사용 원칙

기사에서는 어떤 사건·주장·절차가 보도됐는지 확인한다. 기사나 당사자의 긍부정 논조·평판·찬반 결론을 입력 지표로 쓰지 않는다. 공식 원문을 우선하고 주요 일간지·경제지·종합지·방송사·통신사·외신을 보조로 사용한다.

의혹·수사·기소·재판·판결·확정·불복·취소를 구분한다. 공식 원문 미확보는 공식 판단 부재를 뜻하지 않는다. 기준일 이전 반론·정정·무죄·취소도 읽는다. 독립성의 경제적 의존 판단과 형사 유죄 판단은 별개다.

정관과 판례

정기보고서 시점의 정관을 출발점으로 삼되, 사이에 열린 정기·임시주총의 변경 제안·결과·정정을 연결한다. 제안된 문구를 유효 조항으로 승격하지 않는다. 가결 여부·시행일·적용 대상·부분 개정 범위를 확인한다.

이미지 정관은 외부 OCR·시각 독해 어댑터로 읽을 수 있게 한다. 숫자·부정어·단서·표 열은 원본 위치와 연결한다. 텍스트 구간 전체 확보를 이미지 독해 완료라고 표시하지 않는다. 현재 연결 범위는 로드맵에 둔다.

판례는 사건번호·법원·판단일·공개일·심급·주문과 적용 논점을 기록한다. 판례속보 요약과 판결문 전문을 구분한다. 후속심이나 완전한 유효 정관을 확보했다고 추정하지 않는다.

실행 흐름과 결과 읽기

모델을 교체해도 근거·설정·검증 계약은 유지한다.

  1. 회사·정확한 공고·마감시각·정책·세 설정을 고정한다.
  2. 허용된 원문과 과업을 받는다. 잘린 구간은 이어 읽고 필요한 공시만 더 찾는다.
  3. LLM이 사실·추론·반증·미확인을 인용과 함께 제출한다.
  4. 시스템이 과업·정책·시점·원문·인용 연결과 수치·조건을 검사한다.
  5. 수용된 평가를 후보·구조 규칙에 연결하고 확정 반대와 표결 제약을 보존한다.
  6. 권고와 자동 처리 준비·사람 검토·실행 대기를 따로 반환한다.

후보·선출 구조에는 위 제출 경로가 있다. 모든 안건의 일반 LLM 평가를 제품 권고에 연결하는 공통 단계는 아직 구현 과제다. 별도 보고서 판단을 MCP에 적용된 결과라고 부르지 않는다.

결과에서 확인할 것 의미

인용 문자열과 계약을 통과했다는 것은 해석의 정확성을 보증하지 않는다. 권고가 같아도 사실 귀속이나 현재 직책을 바로잡았다면 별도 개선으로 기록한다.

Appendix

A. 하네스의 고정 조건과 모델 교체

회차·마감시각·정책·원문·설정은 하나의 실행으로 묶는다. 값이 바뀌면 새 과업으로 평가한다. 모델에는 읽을 원문과 판단 지침을 주고 특정 모델의 응답 형식으로 제품 규칙을 고정하지 않는다.

공시 탐색·추가 독해·원문 교체 시 영향받은 과업만 갱신한다. 잘못된 후보 입력 하나는 다른 후보와 격리한다. 예산 종료·조회 실패는 자료 없음으로 바꾸지 않는다. 원문 본문의 지시도 실행하지 않는다.

정관·선출 구조에는 사실·표결 종류를 먼저 고정한 뒤 설정별 판단을 받는 단계별 경로가 있다. guideline_structure={"protocol":"staged"}로 선택한다. 기존 direct 경로는 호환성을 위해 유지하며 단계별 QA를 수행했다고 표시하지 않는다. 전 안건으로의 확장과 모델별 검증 상태는 로드맵에서 관리한다.

A-1. 모델에게 맡기는 일을 네 단계로 나누기

작은 모델에게 한 번에 모든 것을 잘하라고 요구하지 않는다. 원문 판독, 정책 해석, 권고 작성, 반증 점검을 나누고 각 단계에서 필요한 출력만 받는다. 서버는 제출된 결과를 다시 검증한다.

단계 모델이 하는 일 코드가 고정하는 것
사실 판독 주체·기간·전후 조문·제안/시행·개별 표결·미확인 사항을 인용 stance·firmness·automation을 판독 입력에서 제외. 사실·안건·원문 연결 검사
기준별 해석 관련 기준의 불리함·편익·중요성·반증을 설명 이미 읽은 사실과 공백을 유지. 단위·상한 계산과 의존 관계 검사
권고 해석 결과에 stance·firmness를 적용해 찬반·검토 결정 반대 근거·공백·조건을 임의 삭제하거나 안건 유형을 바꾸지 못함
QA 원문이 실제 주장을 지지하는지, 반증·주체·기간·정책·숫자·표결 조건을 다시 확인 현재 판단의 지문에 QA를 결합. 판단 변경·인용 오류·미해결 문제는 해당 안건 수용에서 제외

사실과 표결 종류가 같아야 firmness 효과를 비교할 수 있다. 검증된 사실 묶음은 원문·회차가 같으면 다른 설정과 모델에서 명시적으로 재사용할 수 있다. 사실 재사용 실험과 각 모델이 처음부터 원문을 읽는 실험은 따로 측정한다. 출처나 읽은 구간이 바뀌면 재사용하지 않는다.

해석·권고 단계에는 고정된 사실의 인용문과 추가 독해 손잡이를 전달하고, 최초 판독·QA에는 중복을 제거한 전체 확보 발췌를 전달한다. 이는 문서 전체·이미지 전체를 읽었다는 뜻이 아니다. 필요한 원문은 기존 독해 경로로 다시 요청한다.

StructureWorkbench는 특정 단계와 그 뒤의 판단을 다시 열 수 있다. 잘못된 항목은 거절 기록과 함께 보존하고, 수용된 사실만 다음 판단에 연결한다. QA가 문제를 발견했다고 같은 모델에게 통과 표시만 다시 요구하지 않는다. 해당 사실·해석을 고친 뒤 QA를 새로 받으며 독립 안건은 계속 처리할 수 있다.

A-2. 온톨로지와 유지관리

온톨로지는 자료 → 사실 → 기준 → 판단 → 검토 사이의 연결 규칙이다. 별도 지식그래프 서버는 필요하지 않다. 구조 온톨로지에 기준 ID, 필요한 사실 종류, 원천 탐색 방향과 QA 질문을 둔다. 사실의 필드·타입은 실행 코드의 스키마를 재사용하고, 찬반 기준의 본문은 현재 정책 JSON에서 읽는다.

예를 들어 ES-01은 정관 상한·실제 구성·업무량을 연결한다. ‘7 ≤ 8’ 계산은 코드가 하지만, 대표성에 불리한지는 관련 원문과 정책으로 판단한다. ES-06의 관계 회사 인사 공시는 조사 경로로 지정한다. 이 지정만으로 모든 관계 회사의 공시가 자동 수집됐다고 표시하지 않는다.

기준 ID와 사실 타입·원천 목록 사이의 연결은 회귀 검사로 확인한다. 정책·온톨로지·엔진·원문 변경은 과업과 QA의 재사용 여부에 반영한다. 코드의 계산 결과나 인용 문자열 일치를 의미 정확성으로 승격하지 않는다.

A-3. Luna급 모델에서도 품질을 유지했는지 확인하는 기준

모델은 호출 애플리케이션의 callback으로 교체한다. 서버에 특정 모델 SDK나 유료 호출을 내장하지 않는다. 기본 단계 예산은 adapter당 최대 12회, 단계별 2회 시도, 호출당 45초이며 조정 가능하다. 네 단계 호출 수와 바깥 하네스의 adapter 호출 수를 구분한다. 더 강한 모델로의 자동 전환은 하지 않는다.

단계별 adapter를 VotingHarness에 연결할 때는 바깥 제한도 함께 설정한다. 예를 들어 RunBudget(model_timeout_seconds=600)은 네 단계와 제한된 재시도를 담을 시간을 준다. 기본 바깥 제한 120초를 그대로 쓰면 단계 예산을 다 쓰기 전에 종료할 수 있다. 앱의 callback 구현과 모델 실행 권한은 호출자가 제공한다.

accepted는 계약 수용을 뜻하며 정답 일치를 뜻하지 않는다. 판단 완료·평가 대기·오류·표결 대상 아님을 구분한다. 서버가 원문·평가를 자동으로 영구 저장하지 않으며 사용자가 요청한 결과 보고서는 별도 산출물이다.
