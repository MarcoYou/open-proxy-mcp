완료·현재 구현

  1. 01 설계·정책 계약

    Astra·Fable 관점 통합, 정책 JSON, 후보·구조 평가 계약과 사용자 설정 정의

    범위: 사외·독립이사와 선출 구조의 최소 계약 범위. 범용 고객 정책 운영은 추가 범위다.

  2. 02 실제 MCP 연결

    공개 원문 → 호출 LLM → 제출 검증 → 후보·구조 권고 연결을 실제 MCP에서 확인

    범위: 모든 안건의 공통 LLM 제출 계약이 완료된 것은 아니다.

  3. 03 유연한 LLM 흐름

    원문 직접 판독·추가 독해, 누락 기준 제외, 과업별 오류 격리, 숫자 설정과 자동·수동 분기

    범위: 원천 탐색은 제한된 범위이며 모든 필요한 자료를 찾는다는 보장은 없다.

  4. 04 제품 연결·품질 검증

    전량 비교 12회차·239행 완료. 구조 온톨로지·4단계 판독/해석/권고/QA와 영원무역 2안건 실제 MCP 적용·오류 격리 확인

    남은 확인: Luna 실제 비교, 독립 의미 검증, 전 안건 제출 연결, 경합 선택 처리

배포까지 남음

  1. 05 출시 운영 준비

    출시 범위와 기본값, 정책 활성화·복구, 수동 인계·오류 대응을 검증

    이미 확보한 기반

    실행·정책·설정 연결, 사람 미검토 표시와 수동 지정·증분 조회의 기반 확보

  2. 06 범위 한정 배포

    사용자 요청으로 커밋·푸시 및 main CI 배포 후 live MCP의 과업·제출·최종 권고·분기를 확인

    이미 확보한 기반

    로컬 파일럿과 문서·보고서까지 확인

실측 전 모델 비교·바이어스 검증 설계를 고정한다. 사람 미검토와 유료 API 사용은 허용된 상태다. Luna·Terra·Sol·Astra의 공통 설정, 새 문맥, 원문 시점, 직접/단계별/연산 대조군과 채점자 검증을 분리한다. 현재는 설계 단계이며 이 조건의 모델 비교 결과는 아직 없다. 읽기용 실험 설계서

남은 작업과 완료 기준

아래 순서로 진행한다. 새 파서를 늘리는 것을 완료 조건으로 삼지 않는다. 원문을 직접 읽어 해결할 수 있는지 먼저 보고, 자료가 없으면 해당 기준만 제외해 다른 안건은 계속 처리한다.

순서 할 일 완료로 인정할 증거
1 공통 사실·표결 목록 확정 같은 원문에서 상위/개별 안건, 후보·좌석 수, 가결·부결 조건을 먼저 공유. 동명 후보와 계속 재직자를 구분
2 전 안건 평가 제출 연결 보고서에만 있던 판단을 실제 MCP에 제출하고, 수용·거절 이유와 최종 권고를 JSON·Markdown에서 확인
3 경합·조건·선택 처리 대안별 수용 가능성과 실제 선택 우선순위를 분리. 최대 선택 수·집중투표 배분·철회·조건을 위반하지 않음
4 남은 원문·설명 공백 보강 관계 회사의 인사 공시, 이미지 본문, 후보 수·자리 수 설명을 추가로 읽고 영향받은 행만 갱신
5 의미 품질 검증 같은 설정 반복, 다른 모델·새 표본, 독립 실무 검토에서 사실 귀속·시점·스킵·정책 해석 오류를 별도로 측정

모델 의존도를 낮추는 경로의 이행현황

장치 현재 도달점 남은 검증
4단계 작업 계약 정관·선출 구조에서 사실 → 해석 → 권고 → QA를 별도 입력·스키마로 실행 Luna의 최초 원문 판독부터 반복 실행
사실·표결 범위 고정 투표 성향과 분리한 판독, 명시적 사실 묶음 재사용, 원문 변경 시 무효화 관계·기간·시행 조건의 의미를 잘못 읽는 비율
온톨로지 기준·사실 타입·원천 안내·QA 질문의 연결을 코드와 공유 안내한 모든 원천의 자동 탐색이나 수집 완료를 뜻하지 않음
검증·격리 바뀐 판단에 옛 QA 사용 금지, 오류 항목 기록, 독립 안건 유지 단계별 의미 오류의 자동 수정 전략과 실무 검토
모델·비용 분리 앱 callback 교체, 단계별 예산, 강한 모델 자동 전환 없음 Luna 성능·시간·총 호출량 측정. 비용 절감은 미확인

이 경로는 protocol=staged로 선택한다. 기존 direct 구조 제출과 후보 경로의 동작을 유지한다. 출처 묶음에는 아직 긴 문맥이 들어올 수 있으므로 단계를 나눴다는 사실만으로 작은 모델의 품질을 보장하지 않는다.
