# 원문 수집 안전성 검증

먼저 대상의 `CLAUDE.md`와 [공통 근거 계약](../opm-tool-validation/references/evidence.md)을 읽는다.
이 스킬을 호출했다는 이유만으로 실데이터 수집을 시작하지 않는다. 기존 캐시와 합성 응답으로 먼저 검사한다.

## 검사 경계

수집 함수의 시도 횟수와 실제 HTTP 요청 횟수는 다르다. 클라이언트 내부 재시도, 키 회전,
캐시 miss의 네트워크 fallback까지 추적한다. 제한 수치와 정책은 현재 정본과 실제 클라이언트를 확인하고
과거의 차단 시간·IP/키 가정을 복사하지 않는다. 외부 정책 사실이 필요하면 공식 문서를 확인한다.

## 절차

- 수집 대상 식별자, 상한, 재사용 경로, 새 원문 저장 경로, 중단 조건을 사전에 확정한다.
- 오류별로 `즉시 중단 / 제한된 재시도 / 정상적인 빈 데이터`를 구분한 계약을 먼저 적는다.
  제한·인증 오류 후 다른 키나 프로세스로 우회하지 않는다. 전송 오류의 재시도는 대상 클라이언트의
  명시된 예산·중단 정책과 대조한다. 계약이 불명확하면 REVIEW이며 실제 수집은 보류한다.
- 기존 재사용 가능한 수집기를 먼저 찾는다. [실행 경로](../opm-tool-validation/references/commands.md)를 참고한다.
  새 수집 코드가 필요하면 별도의 구현 요청 범위인지 확인한다.
- 합성 전송 계층으로 성공, 제한 응답, 인증 오류, 전송 오류, 취소를 주입한다.
  발생 순서·요청 시작 횟수·종료 상태를 관찰하고 예외를 삼킨 성공도 잡는다.
- 중단 후 새 요청이 시작되지 않아야 한다. 순차 수집을 기본으로 하며 동시성 구현을 검증할 때는
  **세마포어 대기 중 중단 → 획득 후 재검사**도 시험한다. 이미 진행 중인 요청은 별도 집계한다.
- 기록에서 `오류 발생 → 중단 조건 성립/신호 → 각 전송 시작`의 순서를 구분한다.
  최종 `aborted=true`만으로 앞선 재시도가 중단 이후였다고 단정하지 않는다.
  즉시 중단 계약이면 해당 오류 시점 이후 신규 전송이 실패이고, 재시도 허용 계약이면 예산과 신호 이후 전송을 검사한다.
- 성공·실패 경로 모두 대기·자원 정리가 적용되는지 검사한다. 내부 재시도가 중단 정책을 위반하면
  수집기 바깥의 `break`만으로 안전하다고 판정하지 않는다.
- 같은 입력의 중복 요청, 동시 실행, 기존 파일 덮어쓰기, 압축/비압축 중복, 깨진 캐시를 검사한다.
  잘못된 캐시는 조용히 재수집하지 말고 원인을 드러낸다.
- 전체 문서 응답 경계를 저장하고 원본 바이트의 해시를 남긴다. 요약문·파서 출력만 저장하지 않는다.
  원문·정답·실행 증거는 분리하고 공개 저장소 밖의 지정 경로를 쓴다.
- URL·예외·로그·fixture에 실제 키의 일부라도 남지 않는지 합성 표식으로 검사한다.

## 통과 조건과 한계

예산 준수, 재사용 시 외부 호출 없음, 중단 이후 신규 호출 없음, 원문 무변경, 실패 종료와 비노출이
관찰 가능한 테스트로 입증되어야 PASS다. 실제 전송 계층을 측정하지 않았다면 `fetch_attempts`를
HTTP 요청 수라고 쓰지 말고 제한사항에 적는다.

실제 수집이 필요한데 승인된 범위·입력·저장 위치가 없거나 중단 결함이 남아 있으면 BLOCKED로 멈춘다.
검증 에이전트에게 API 키를 전달하거나 각자 수집하도록 하지 않는다. 수집은 중앙 담당자만 수행한다.
