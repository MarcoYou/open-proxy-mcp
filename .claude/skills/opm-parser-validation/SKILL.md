# 파싱과 지표 정확도 검증

먼저 대상의 `CLAUDE.md`와 [공통 근거 계약](../opm-tool-validation/references/evidence.md)을 읽는다.
함수 단위 검사는 이 단계의 근거다. 전체 도구 검증에는 MCP·출력 단계를 추가한다.

## 정답과 표본을 먼저 고정

- 검증할 필드, 단위, 정규화 규칙, 제외 조건, 정확/검토필요/미측정의 뜻을 명시한다.
- 입력은 DART 응답 경계다. 문서 파싱은 `get_document_cached` 반환 형태를 보존하고
  파서의 중간 출력으로 원문을 대체하지 않는다. 평가 도중 누락 캐시를 온라인으로 채우지 않는다.
- 원문 판독자가 파서 출력을 보지 않고 정답과 근거 위치를 기록한다. 에이전트의 역할·자격을
  실제 전문가 승인처럼 표시하지 않는다. 애매한 라벨은 검토필요로 분리한다.
- 실제 대상 필드가 있는 양성 표본, 대상이 없는 음성 표본, 애매한 표본을 분리한다.
  임기 열이 없는 공시의 통과는 임기 추출의 양성 근거가 아니다.
- 회사 그룹·정정공시·연도를 고려해 개발 표본과 별도 검증 표본을 나눈다.
  반복해서 보고 수정에 쓴 표본은 더 이상 미지의 검증 표본이라고 부르지 않는다.

## 비교

- [분야별 기준](references/profiles.md)에서 해당 부분만 읽는다.
- 동일 원문·정답·평가기 버전으로 **실제 이전 코드와 수정 코드**를 각각 실행한다.
  예전 로직을 새로 흉내 낸 함수로 기준선을 대체하지 않는다.
- 문서·대상 개수의 분모를 유지하고 입력별 통과/실패/오류/제외를 모두 기록한다.
  빈 정답이 유효한 음성인지 입력 누락인지 구별한다. 이를 지원하지 않는 평가기는 범위를 확장했다고 주장할 수 없다.
- 정확한 값뿐 아니라 대상과 필드의 결합, 등장 횟수, 잘못 추가한 값, 침묵 누락을 검사한다.
  수치가 커지거나 작아졌다는 사실만으로 개선·회귀를 판정하지 않는다.
- 파서가 예외를 삼키더라도 외부 네트워크 시도를 실패로 잡는다.
  캐시 없는 입력, 비어 있는 목록, 원문 해시 변경은 성공으로 건너뛰지 않는다.
- 별도 검토자는 실패 표본과 일부 통과 표본의 원문을 다시 읽는다. 새 평가기나 정답 오류가 의심되면
  [측정기 검사](../opm-validation-audit/SKILL.md)로 돌린다.

## 개선 요청일 때만

원인 분류 → 실패 테스트 추가 → 최소 수정 → 같은 개발 표본 재검사 → 별도 검증 표본 확인.
정답이나 표본을 바꿔야 하면 근거를 독립 검토하고 버전을 올려 양쪽 코드를 다시 측정한다.
진단 요청이면 수정 단계 직전에 멈춘다.

## 통과와 범위

합의한 필드에서 알려진 중대 오답과 새로운 회귀가 없고, 양성·음성·애매 사례가 각자 평가되어야 한다.
합성 표본만 있으면 합성 범위 PASS로 한정한다. 실제 정확도 주장을 요청받았는데 해당 양성 근거가
없으면 REVIEW다. 시장 전체 주장은 층별 표본·미측정·분모·오류율의 불확실성까지 별도로 보고한다.
