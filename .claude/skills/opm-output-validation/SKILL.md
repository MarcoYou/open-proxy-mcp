# 사람에게 전달되는 결과 검증

대상 저장소 지침과 [공통 근거 계약](../opm-tool-validation/references/evidence.md)을 읽는다.
문서만 검토할지, 도구 출력 변경인지, 대시보드 소비 경로까지인지 먼저 구분한다.

## 출력 변경

- 같은 원문 응답, 입력 인자, 코드 버전을 식별한 before/after를 사용한다.
  라이브에서 다시 가져온 문서가 바뀌었다면 코드 차이의 증거로 쓰지 않는다.
- 사람·역할·값·단위·기간·상태·출처를 결합해서 비교한다. 이름이나 숫자의 집합만 같아도
  다른 사람에게 붙은 값, 바뀐 단위, 중복 소실은 오류다.
- 정수·소수·음수·날짜·횟수·단위·표 행·경고·검토필요 표시를 확인한다.
  `3년 → 3개월`, 이름과 임기의 행 교환, 같은 값의 중복 소실을 음성 대조로 쓴다.
- 빈 응답, 잘린 응답, 예외 메시지, 원문 링크 소실을 검사한다.
  정상적인 요약을 허용하되 원문과 넓혀 볼 경로를 없애지 않는다.
- 기존 숫자 비교기와 식별자 스캐너는 보조 경보다. 경보가 없다고 의미 보존 PASS로 판정하지 않는다.
- 도구 출력 변경은 [MCP 검사](../opm-mcp-validation/SKILL.md)의 실제 응답으로 확인한다.

## 문서만 검토

- 처음 읽는 사람이 목적 → 필요한 입력 → 실행 예 → 결과 해석 → 한계 → 다음 행동을 따라갈 수 있는가?
- 문서의 인자·출력 예를 실제 계약과 대조한다. 가능하면 오프라인 예제를 실행한다.
- 고객·회사·브랜드 사례는 익명화하되 필요한 서비스명·프로토콜 토큰·법령·출처는 보존한다.
  영어 일반 단어와 회사명이 겹친다고 전역 치환하지 않는다.
- 원문·회귀 입력·데이터 파일은 문서 마스킹으로 바꾸지 않는다. 예시 식별자는 교체가 필요함을 알린다.
- 검토 요청이면 발견사항과 교정안을 보고하고 문서는 바꾸지 않는다. 수정 요청일 때만
  [문서 운영 규칙](../../../wiki/wiki_schema.md)에 따라 정본을 고치고 관련 검사를 실행한다.

## 대시보드가 범위에 있을 때

서버 결과뿐 아니라 소비 측의 필드 매핑·정렬·빈 상태·기간 단위·검토필요 표시까지 확인한다.
독립 미리보기 CLI의 통과를 운영 수집기·DB·화면 연결 완료로 보고하지 않는다.
사용자가 요청한 기존 프로젝트에서 검사하고, 새 프로젝트 생성·운영 데이터 적재·배포는 자동으로 하지 않는다.

## 판정

기계 대조와 독자 관점의 의미 검수를 구분해서 기록한다. 발견한 의미 손실은 FAIL,
근거 부족·도메인 해석 불일치는 REVIEW다. 화면을 열지 않았다면 화면 검증은 NOT_RUN이다.
