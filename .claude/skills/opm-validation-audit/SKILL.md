# 검증 체계 자체의 검사

파서보다 측정기가 먼저 틀릴 수 있다. 대상 `CLAUDE.md`와
[공통 근거 계약](../opm-tool-validation/references/evidence.md)을 읽는다.
점검 요청은 자동 수정·수집·배포 권한이 아니다.

## 계약과 구현 대조

- 스킬의 참조 파일·명령·실행 환경·최신 계약이 실제로 존재하는지 확인한다.
  수정일만으로 최신성을 판단하지 않는다. 동명 사본이 다른 절차를 가리키는지도 본다.
- 주장하는 범위와 평가기가 읽는 필드를 대조한다. 임기를 안 읽는 평가기가 후보 이름을 맞혔다고
  임기 정확도를 보증할 수 없다.
- 실제 코드와 측정 코드의 경로, 원문·정답·평가기 해시, 실행 도중 코드 변경을 확인한다.
- 비밀정보가 없는 고정 원문과 독립 라벨을 사용한다. 정답을 파서 출력으로 생성하거나,
  서로 같은 파서를 쓰는 에이전트의 합의를 독립 판독이라고 부르지 않는다.

## 거짓 통과를 깨는 시험

해당 도구에 관련 있는 경우만 고르고, **판정·종료 코드·실제 호출·산출물**을 관찰한다.

| 주입할 문제 | 관찰할 결과 |
|---|---|
| 빈 corpus, 누락 파일, 중복 사례 | 성공이 아닌 명시적 입력 오류 |
| 입력·정답·하네스 변경 후 이전 보고서 재사용 | 비교 불가 또는 양쪽 재측정 |
| 파서의 네트워크 시도와 예외 삼킴 | 외부 호출 차단 및 실패 기록 |
| 잘못된 역할·단위·사람-값 연결·중복 소실 | 의미나 정확도 검사에서 실패 |
| 원문과 불일치하는 라벨 | 독립 재판독으로 분리, 파서를 라벨에 억지로 맞추지 않음 |
| 필수 단계 누락, 빈 근거, 변조된 근거 파일 | 전체 PASS 차단 |
| 수집 중단과 대기 작업의 경합 | 중단 이후 새 요청 시작 차단 |
| 없는 기능·경로를 가리키는 지침 | 사용 불가와 필요한 환경을 드러냄 |

실패를 주입해도 초록이면 해당 검사기는 통과 근거로 사용하지 않는다.
정상 대조도 함께 돌려 언제나 실패하는 검사기를 좋은 검사기로 오해하지 않는다.

## 스킬 행동 검증

형식 검사만으로 판단하지 않는다. 실제 사용 요청과 최소 원문을 주고 어떤 단계·결론·권한을 선택하는지 본다.
복합·고위험 스킬 신설/개정에서는 사용 가능한 독립 검토자에게 블라인드 시나리오 평가를 맡긴다.
의도한 정답·의심한 버그·이전 결론은 알려주지 않는다. 입력과 권한 경계만 제공한다.
외부 호출·운영 변경 없이 평가하고, 독립 평가가 불가능하면 자기 점검이라고 명시한다.

발견사항은 재현 근거·영향·교정안으로 기록한다. 변경 권한이 있으면 실패 사례를 먼저 남기고 좁게 수정한 뒤 재검사한다.
스킬을 고친 경우 절차와 평가 시나리오도 함께 갱신하되, 사용하지 않는 과거 규칙을 계속 누적하지 않는다.
