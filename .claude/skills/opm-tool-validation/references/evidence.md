# 검증 근거 계약

## 실행 기록

실행마다 다음을 기록한다. 재사용 시점이 아니라 실제 실행 시점과 대상 버전을 쓴다.

- 목적/프로필/요청 범위/허용된 작업, 저장소·코드 버전과 미커밋 변경 지문, 실행 환경.
- 원문 목록과 해시, 라벨 버전·해시, 평가기 버전·해시, before/after 식별.
- 검증 필드·제외 조건·정규화 규칙·허용 오차와 실제 표본/합성 표본 구분.
- 요청·평가·통과·실패·오류·제외·미측정 수, 필드별 양성·음성·애매 사례 수.
- 재현 명령, 종료 코드, 근거 파일, 독립 판독/검토 여부, 외부 호출 여부.
- 알려진 한계, 발견사항, 남은 단계, 다음 행동과 승인 필요 여부.

회귀 없는 것과 정확한 것은 다르다. before/after가 같은 오답이면 회귀가 없어도 정확도 실패다.
분모가 없거나 비어 있으면 정확도 수치를 만들지 않는다. 관련 없는 많은 테스트의 통과로 대상 필드 검사를 대체하지 않는다.

## 단계 상태

| 상태 | 의미 |
|---|---|
| `PASS` | 명시된 범위와 기준에서 근거가 있는 통과 |
| `FAIL` | 실제 불일치·회귀·안전성 위반 관찰 |
| `REVIEW` | 자료는 있으나 의미/정답/충분성의 판단이 남음 |
| `BLOCKED` | 권한·입력·환경이 없어 필요한 검증을 진행할 수 없음 |
| `NOT_RUN` | 아직 실행하지 않음 |
| `SKIP` | 이번 주장에 적용되지 않음. 이유 필요, 필수 단계에는 불가 |

필수 단계의 PASS 이외 상태는 전체 통과를 막는다. 선택 단계에서 발견한 FAIL/REVIEW/BLOCKED도 숨기지 않는다.
외부 호출 없는 앱 내부 검사, 별도 pilot, live를 구분한다. 실제 운영 확인이 없으면 배포 성공이라고 쓰지 않는다.

## 기계 판정용 보고서

[check_report.py](../scripts/check_report.py)는 다음 JSON을 읽는다. 원문·키를 보고서에 넣지 않는다.
파일과 근거는 지정된 비공개/임시 폴더에 저장하며 덮어쓰지 않도록 실행별 이름을 쓴다.
아래는 구조 예시이며 `sha256`은 실제 증거 파일의 바이트 해시로 바꾼다.

```json
{
  "schema_version": 1,
  "profiles": ["skill"],
  "claim": "offline",
  "limitations": ["실제 시장 표본 또는 운영 배포는 확인하지 않음"],
  "stages": [{
    "id": "harness",
    "status": "PASS",
    "scope": "보고서 판정기의 정상·실패 대조와 스킬 행동 시나리오",
    "reason": "검사 종료 코드와 시나리오 판정 확인",
    "evidence": [{"path": "checks.txt", "sha256": "실제 SHA-256"}]
  }]
}
```

프로필은 [워크플로우 표](workflow.md)에 정의한 이름의 비어 있지 않은 중복 없는 목록이다.
단계는 `harness`, `collection`, `corpus`, `parser`, `mcp`, `output`, `consumer`, `pilot`, `live`만 허용한다.
단계의 `scope`는 비어 있으면 안 된다. PASS에는 존재하는 비어 있지 않은 근거 파일과 일치하는 해시가 필요하다.
PASS 외 상태는 `reason`도 필요하다. 근거 경로는 보고서 기준 상대 경로 또는 명시적 절대 경로다.
입력 JSON의 중복 키, 알 수 없는 필드·상태, 중복 단계, 자기 자신을 근거로 삼는 보고서는 거부한다.

```bash
python3 /path/to/skills/opm-tool-validation/scripts/check_report.py /private/run/report.json
```

| 종료 코드 | 의미 |
|---|---|
| `0` | 필요한 단계에 근거 있는 PASS가 기록됨 |
| `1` | 미통과/미실행/필수 단계 누락/근거 무결성 오류로 통과 차단 |
| `2` | 보고서를 읽거나 계약대로 해석할 수 없음 |

**한계:** 이 검사기는 보고서를 취합하는 안전장치다. 근거 파일이 진실인지, 테스트가 실제로 무엇을 보았는지,
표본이 대표적인지, 정답이 맞는지는 독립 검토해야 한다. 임의 텍스트에 PASS를 붙여도 진실이 되지는 않는다.
이 도구는 네트워크·테스트·수집·파서 수정·배포를 실행하지 않으며 키가 필요하지 않다.
