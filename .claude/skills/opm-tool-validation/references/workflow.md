# 목적별 검증 워크플로우

이 문서는 검증 순서와 중단 조건의 정본이다. 스킬은 판단 절차이며 상시 실행 서비스가 아니다.
예약 실행, 자동 데이터 수집, 자동 병합·배포는 별도 요청과 구현 없이는 작동하지 않는다.

## 실행 전 정할 것

- 요청이 진단인지 개선인지, 검증할 코드 폴더와 비교할 이전 코드.
- 검증 프로필, 대상 필드·도구·화면, 통과 기준, 이번에 주장하지 않을 범위.
- 사용 가능한 원문·독립 정답과 실행 환경. 없으면 합성 검사와 실표본 검증을 구별한다.
- 이번 실행의 시간·반복 예산과 허용된 외부 호출. 별도 합의가 없으면 외부 호출은 하지 않고
  개선 반복은 최대 세 회로 제안한다. 예산을 다 쓰면 남은 실패를 보고하고 무한 재시도하지 않는다.

## 목적별 필수 단계

아래 식별자는 [보고서 검사기](../scripts/check_report.py)가 사용하는 이름이다.
범위를 좁히는 것은 가능하지만 넓은 결론을 유지한 채 필수 단계를 빼지는 않는다.

| 프로필 | 필요한 단계 | 선택되는 전문 스킬 |
|---|---|---|
| `collection` 수집기 변경 | `harness → collection` | 측정기, 수집 안전성 |
| `parser` 파싱 변경 | `harness → corpus → parser → mcp → output` | 측정기, 파싱, MCP, 출력 |
| `mcp` 호출 계약 변경 | `harness → mcp` | 측정기, MCP |
| `output` 도구 출력 변경 | `harness → mcp → output` | 측정기, MCP, 출력 |
| `docs` 설명 문서 검토 | `output` | 출력·문서 |
| `consumer` 대시보드 연결 변경 | `harness → mcp → output → consumer` | 측정기, MCP, 출력의 소비 측 검사 |
| `skill` 검증 체계 변경 | `harness` | 측정기 |

여러 목적을 동시에 바꾸면 해당 프로필을 모두 선택하고 필수 단계의 합집합을 적용한다.
파싱 검증 중 추가 수집이 필요하면 `collection` 프로필도 포함한다.
`corpus`는 파싱 스킬의 원문 무결성·독립 라벨·표본 범위 검사다.
기존의 동일 평가기 검사 근거를 재사용할 때는 코드·환경·계약이 여전히 일치하는지 확인한다.

## 상태 흐름

```text
범위·권한·예산 확정
  → 측정기 검사 → 원문/정답 고정 → 이전 코드 측정
  → 실패 원인 분류
      원문/캐시 오류 → 복구 범위 확인 → 새 원문 버전 → 양쪽 재측정
      정답 오류     → 독립 재판독 → 정답 버전 갱신 → 양쪽 재측정
      평가기 오류   → 평가기 실패 테스트 → 교정 → 양쪽 재측정
      파서 오류     → 실패 테스트 → 최소 수정 → 동일 개발 표본 재검사
  → 별도 검증 표본 → 실제 MCP 응답 → 독자/소비 측 검사
  → 근거 합치기 → 통과 범위와 미검증 범위 보고
```

프로필에 없는 단계는 생략할 수 있다. 진단 요청이면 원인과 권고를 보고하고 수정 전 멈춘다.
파서 결과를 정답에 복사해 통과시키지 않는다. 같은 입력·정답·평가기의 비교가 깨졌다면
이전 결과와 이어 붙이지 말고 새 버전으로 양쪽을 측정한다.

## 실패 후 반복

- 재현된 실패를 익명화한 회귀 사례와 근거로 남기고, 발견·수정·재검증 결과를 분리한다.
- 실패 사례만 재실행하지 말고 전에 맞던 사례도 확인한다. 반복해서 사용한 holdout은 개발 표본으로 돌린다.
- 불확실한 의미는 REVIEW로 남긴다. 자동 확정하려고 라벨 기준을 느슨하게 만들지 않는다.
- 새 권한 필요, 입력/정답 부재, 안전성 위반, 반복 예산 소진, 같은 실패에 진전 없음이면 멈추고 다음 선택을 보고한다.
- 학습의 산출물은 검토된 실패 사례·정답·테스트·파서 변경이다. 모델 가중치의 자동 학습이 아니다.

## 통과와 배포는 분리

`claim=offline`은 고정 입력/앱 내부 범위다. `pilot` 주장은 별도 로컬 서버 확인 단계가,
`live` 주장은 pilot와 운영 서버 확인 단계가 추가로 필요하다. 검사기가 이 단계를 실행해 주지는 않는다.
통과 보고서가 있어도 커밋·푸시·병합·배포·운영 적재 권한은 생기지 않는다.
승인된 배포가 있다면 대상 저장소의 배포 절차를 따르고, 실제 운영 확인은 별도 증거로 남긴다.

## 유지관리

- 새 스킬은 역할별로 짧게 유지한다. 호출 제한·배포 정책은 `CLAUDE.md`를 참조하고 숫자를 복제하지 않는다.
- 정본은 저장소의 `.claude/skills/opm-*`다. Codex 설치 경로에는 정본을 가리키는 링크를 둔다.
  `.agents`의 옛 이름은 정본 안내만 한다. 다른 checkout의 옛 본문은 그대로 실행하지 않는다.
- CLI 인자·MCP 계약·원문 경계·라벨 기준 변경, 또는 거짓 통과 발견 시 해당 스킬과 행동 시험을 다시 검토한다.
- 검증 체계 변경 시 형식/링크 검사 + 정상/실패 대조 + 독립 시나리오 평가를 수행한다.
  환경상 독립 평가를 못 했으면 생략 사실을 기록한다. 수정일을 최신성 보증으로 사용하지 않는다.
- 실표본·고객명·실행 기록은 private에, 공개 절차와 합성 시험만 공개 저장소에 둔다.
